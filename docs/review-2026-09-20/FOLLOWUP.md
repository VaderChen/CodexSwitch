後續修正紀錄

本輪延續第一輪修正，維持 Go 1.27.1，針對已重現的資料、路徑及非同步操作問題追加修正。

| 項目 | 觸發情境與修正 |
| --- | --- |
| Unicode 路徑別名 | 尚未建立的 `café` 與 `café` 可能是同一目的檔；原交易會成功卻讓第二份資料覆蓋第一份。現在按實際磁碟規則比對並在寫入前拒絕衝突，包含父目錄及 `.bak` 別名。 |
| 符號連結與上層路徑 | 對 `link/../home` 先做字串清理會走到連結所在位置的上層，與實際系統解析不同。現在先解析符號連結再處理 `..`；設定、程序辨識與未建立子目錄使用一致解析，無法確認的懸空連結會拒絕。一般設定仍保留使用者輸入的目錄別名。 |
| Shell 環境檔 | 從另一帳號的 Shell 載入匯出環境時，舊 `CODEX_USER_DATA_DIR` 會殘留並優先於新 `USER_DATA_DIR`。現在同步設定兩者，含空白與單引號的路徑仍正確引用。 |
| 設定表單競態 | defaults 回應延遲時，快速操作可讓另一帳號的回應覆蓋表單。現在立即保留帳號與對話框、載入期間禁止修改、關閉後忽略過期回應；儲存與重新整理完成後才關閉。 |
| 過期帳號列表 | 舊的讀取回應可能晚於移除後的刷新回來，讓已刪除帳號重現。現在只接受最新請求的結果或錯誤。 |
| 重繪後焦點 | 對話框開啟期間列表重繪會移除原按鈕。現在以帳號 ID 與操作找回新按鈕；帳號已移除時回到刷新按鈕。 |
| 過期用量回應 | 刪除後重新加入相同 ID，或重置後重新查詢，舊請求可能覆蓋新用量。現在使用服務內遞增請求編號確認結果仍屬於當前查詢，失效回應不寫回。 |
| 匯出破壞資料鎖 | 將匯出目的地選為使用中的帳號檔或鎖檔，可能覆寫舊快照或替換受鎖定的 inode。現在拒絕這些目的地及其實體別名，並在選定檔案後才取得匯出快照。 |
| 關閉後的背景寫入 | store 釋放排他鎖後，晚到的背景工作仍可寫入並覆蓋新實例的資料。現在關閉狀態在同一 mutex 下設定，後續寫入拒絕且還原記憶體。 |
| 建置失敗保全 | 原腳本通過工具鏈檢查後立即刪除 dist，編譯錯誤會失去上一版產物。現在完整建置與檢查成功後才以 `dist.bak` 暫存並替換；既有備份會阻止建置。run.command 也等建置成功後才關閉舊 App。 |

Unicode 比對不依賴把字串轉小寫的近似規則。Apple 文件記載 [APFS 與 HFS+ 採用不同 Unicode 規則](https://developer.apple.com/library/archive/documentation/FileManagement/Conceptual/APFS_Guide/FAQ/FAQ.html)，而 [HFS+ 格式規格](https://developer.apple.com/library/archive/technotes/tn/tn1150.html)另有特殊比較規則。因此，既有路徑使用實際檔案身分；只有比較不同且尚未建立的 Unicode 名稱時，才在既有父目錄建立短命 0700 私有探測目錄與 0600 空檔，直接核對磁碟行為後移除。無法安全探測或清理時回傳錯誤，停止交易。ASCII 名稱仍使用磁碟大小寫設定。

帳號、OAuth、重置與用量測試使用模擬資料或本機測試服務；更新安裝流程以隔離的模擬 App 驗證回復行為。
